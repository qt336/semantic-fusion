# GPT 转接通道：额外输入与请求隔离核验

本页记录 API 可用性或参数诊断。基准成绩和纳入数见[统一结果表](../README.md)。

更新时间：2026-11-24T19:18:04.722851+08:00

**结论：没有检测到前一道题或答案自动串入，但已确认请求参数会被通道转换，且存在约 3,744–3,747 token 的额外输入。完整附加文本未取得，不能把这些 GPT 结果当作上下文已经受控的无思维链实验。**

## 3,700 多输入 token 的实际分解

例如 `pilot_sol56_000.json`：客户端仅提交 `画完刀。直接问“刀”的前一个字是什么？只输出一个字即可。`，响应 `usage.attribution.items` 将 3,769 个输入 token 分解如下。归属统计没有给出前三条消息的角色和文本。

| 归属项 | 输入 token | 已知信息 |
|---|---:|---|
| 重复消息一 | 3556 | 在本轮 184 个成功响应中 ID 与计数相同；文本未取得 |
| 重复消息二 | 72 | 在本轮 184 个成功响应中 ID 与计数相同；文本未取得 |
| 模板消息三 | 115 | 全轮存在 114、115、117 三种计数，对应少数重复 ID；文本未取得 |
| 当前问题对应输入项 | 24 | 本地请求仅有这一题 |
| 本次生成答案项的输入计数 | 2 | 属于本次输出项的输入侧开销，不能当作已发现的历史答案 |
| 合计 | 3769 | 3556 + 72 + 115 + 24 + 2 |

180 道题的当前问题输入为 21–31 token；扣掉问题后，额外输入只出现 3744、3745、3747 三种数值，没有随着题目数量累积增长。固定 ID 和计数支持“重复前缀/模板”的解释，不能独立证明消息内容逐字不变。

平台自身文档 明确说明其 Chat Completions 是由 Responses 转换得到，并会以 Codex 默认 instructions 替换 system prompt。该说明为固定 Codex 指令的解释提供线索，**但文档没有逐条解释本轮 Responses 接口的三个附加消息，不能把 3556 token 的全文或具体作用说成已证实。**

## 本地脚本和历史关联

核对了原始请求体和发送代码：客户端未传 conversation、previous_response_id、system、tools 或历史消息；评分用的 gold 字段保存在本地记录中，不作为独立字段发送。脚本未读取或拼接本聊天的长对话。新的隔离测试还保存了 requests 实际准备发送的 JSON 字节及其哈希。

| 数据目录 | 成功响应 | 非空 previous_response_id | 指向任何已保存响应 | 输入项复用已保存输出 ID |
|---|---:|---:|---:|---:|
| gpt_none_20261124 | 382 | 258 | 0 | 0 |
| gpt56sol_none_20261124 | 184 | 184 | 0 | 0 |

上述记录包含基准与连通性/参数对照。GPT-5.6 的 184 个 previous_response_id 全部不同，没有一个对应我们保存的前一道返回。原始响应中有且只有四条纯输入项（三条重复/模板项和当前问题），加上一个本次生成输出项。没有看到先前题目或答案的消息 ID 被直接复用。若服务端重写 ID 或做摘要，这种检查不能排除它。

## 六轮随机标记隔离测试

每轮先在独立请求中发送一个新随机 AUDIT 标记并要求 ACK；随后另发请求询问此前标记，但不在请求体中提供标记或历史。前三轮沿用基准参数，后三轮增加 previous_response_id=null 和 reasoning.context=current_turn。

| 轮次 | 显式清空历史并指定 current_turn | 独立请求回答 | 恢复上一标记 |
|---|---|---|---|
| 1 | 否 | NONE | 否 |
| 2 | 否 | NONE | 否 |
| 3 | 否 | NONE | 否 |
| 4 | 是 | NONE | 否 |
| 5 | 是 | NONE | 否 |
| 6 | 是 | NONE | 否 |

六轮均为 HTTP 200，独立请求全部回答 NONE。正对照将“标记消息、ACK、查询”明确放入同一个请求的历史数组，模型正确返回随机标记。另一个正对照只提供前一响应 ID，模型回答 NONE，返回的 previous_response_id 也被换成不同的 ID。前一响应使用 store=false，因此这个 ID 正对照不用于证明官方存储语义；它明确表明当前转接通道不能按客户端给出的 ID 恢复该测试历史。

**有限结论：这些测试没有观察到隐式跨请求记忆；不能据六轮负结果保证所有路由、账户、请求均无历史污染。**

## 参数是否被保留

- 显式 previous_response_id=null：仍返回非空 ID。
- 显式 reasoning.context=current_turn：返回 all_turns。
- 新的 prompt_cache_key：返回另一个键；in_memory 保留策略返回 24h。
- instructions=""：三条附加输入仍在，输入总量没有消失。
- store=true：响应仍返回 store=false。
- 把 input 字符串换成单 user 消息数组或 input_text 数组：仍返回三条附加输入和非空 previous_response_id。

因此不能用这些开关宣称已清空服务端上下文。all_turns 或非空 previous_response_id 本身也不证明前题被带入；当前字段显然经过转接，不能直接套用官方直连的解释。

## 能否取得附加文本

GET 当前响应、当前 input_items、上一响应、上一 input_items，以及显式请求 store=true 后的 input_items，最终均返回通用 `404 page not found`；其中一次 TLS 失败已保留并补查一次，补查也是 404。没有取得实际输入文本，也没有取得服务端变换后的请求体。

要逐字确认这三条附加消息，以及 previous_response_id 对应的上游步骤，需要平台提供脱敏后的上游完整请求/关联响应日志，或者提供能读取完整输入且保证独立请求的接口。当前公开接口的观察不足以断言它们含有历史答案，也不足以完全排除。

## 对已有结果的处理

保留全部原始输出和正确率；标为“转接通道、额外上下文未核实”。暂不把 GPT 的高正确率用于判断受控无思维链条件下的理论支持或反例。这个限制适用于该通道的 GPT-6 Sol、GPT-6.1 Terra、GPT-6.2 诊断和 GPT-5.6 Sol。不影响其他通道已有实验的原始记录，也没有修改论文或正式结果表。

文件：`audit.py` 为网络检查脚本；`marker_manifest.json` 为随机标记；各请求原始 JSON 包含准备发送的请求体、服务器响应和计数；`report.py` 可重新生成本报告；`summary.json` 为结构化核验结果。
